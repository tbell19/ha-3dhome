# History and decisions

## Timeline

1. **2D isometric SVG (v1–v2).** Started as a hand-tuned isometric drawing of one home, generated by a Python script.
2. **Data-driven scene.** The art moved into a scene JSON rendered in the browser, with a topological painter's sort and light glows clipped per room. Edits became cheap JSON patches.
3. **Lighting pass.** Track lights with crossing beams, walls raised to 60 units, and fan bulbs merged so each fan has one tap target (tap toggles, hold opens details).
4. **3D rewrite (v3).** Three.js r160, orthographic camera, real point/spot lights, static shadows, HTML chips projected from 3D. It reuses the same scene JSON.
5. **Editor (v4.0).**
   - Move, rotate, duplicate, delete, group, undo; save back to the dashboard.
   - The Sweet Home 3D library browser, using the Downloader integration.
   - The 2D view was removed.
6. **Dashboard strategy (v4.1).** The dashboard became `strategy: custom:iso-home`, a full-screen map.
7. **Camera and rooms (v4.2).** Map-style controls, animated fly-to, room menu, direct drag-to-move, keyboard nudges.
8. **Any entity (v4.3).** The Add panel lists every HA entity with drag-and-drop, plus the Show as menu.
9. **Screens (v4.4).** Media players and cameras as 16:9 screens with live artwork and an ambient glow.
10. **Mobile editor (v4.5).** Compact UI. Touch-safe dragging: select first, two fingers always move the camera. No gizmo on touch. Drag-to-rotate.
11. **Repo.** Code, live layout snapshot, smoke tests, minified build and docs moved into git.
12. **Memory leak fix (v4.6).** Firefox slowed down over long sessions. HA regenerates strategy dashboards on registry changes and calls `setConfig` each time, and every call built a new WebGL context without releasing the old one.
    - Now: identical configs are ignored, `_teardown()` releases the context and all GPU resources, detached cards free themselves after 30 s, and rendering pauses in hidden tabs.
    - Editor rebuilds also stopped leaking shadow-map textures.
    - Added `tools/leak-test.js` to measure all of this.
13. **Floor plan editor (v4.7).** Edit mode gained a 🛋 Furniture / 📐 Floor plan switch.
    - Walls became free segments (`wall_segs`) with draggable corners.
    - Doors and windows became negative boxes (`openings`) that cut whatever walls they pass through.
    - A blueprint image can be uploaded, scaled from a known length and traced.
    - Existing walls are converted automatically and render the same (0.1% pixel difference, from closed corners).
14. **Rooms in the plan editor (v4.8).** Room floors became editable plan items: select, drag corners, add or remove corners, draw new rooms, rename, recolour, hide from the menu.
    - Room labels with areas appear in plan mode.
    - Click-cycling fixes overlapping walls being unselectable, and thin walls get a minimum on-screen click width.
    - The plan mode has no gizmo, and the toolbar no longer wraps at half width.
15. **Real sun (v4.9).** The sun follows `sun.sun`'s azimuth and elevation (or is computed from the home location), turned by a configurable `scene.north`, with a smooth dawn/dusk fade and warm low sun. An invisible roof keeps sunlight to windows and doors. The editor has a north field, a north arrow and a time-of-day preview.
16. **Smoother saves and real wall heights (v4.9.1).**
    - Saving made HA swap in a new card element, which built a second WebGL scene from scratch (reset camera, reloaded models) while the old one waited 30 s to free itself. Detached cards now park, and the replacement adopts the parked one (`PARKED`, `_kick()`); config comparison ignores key order (`stableJSON`), and save records the exact config the strategy regenerates.
    - The roof sits over the tallest wall, and every wall is raised to it in the shadow pass, so wall tops are no longer sunlit.
    - Floor plan mode shows walls at their real height (no chest-height slice). Door and window markers draw on top, clicks prefer them over the wall above, and the sun is overhead so walls don't shadow the plan.
17. **Surface textures (v4.9.2).** Walls and room floors can take a subtle procedural texture (wood, tile, stone, carpet, concrete, brick, plaster) on top of their colour, keeping the simple look but not perfectly flat. Textures are canvas-drawn (no downloads), world-scaled so they line up across wall pieces, and shared and disposed like the cached materials.
    - Each texture is tagged for walls, floors or both, and the pickers only list the ones that fit; wood panelling was added for walls.
    - Door openings can hold a 3D door (solid, glass, double, sliding, barn, garage) tied to a sensor, animating open and shut (`DOOR_STYLES`, `_buildDoorLeaf`, `_setDoors`).
    - v4.9.3: lights can build their own fixture (can, ceiling, pendant, bulb, floor lamp, table lamp, string). String lights are procedural: bulbs by count or spacing along a sagging cord, with draggable points (`FIXTURES`, `stringBulbs`, `_buildFixture`, `_buildStringHandles`).
    - v4.9.2 also merged two sessions that had both shipped as 4.9.0 (sun and roof, then textures). The textures upload replaced the sun build, so 4.9.2 is the combined release.
18. **Render looks (v4.10).** The render looked flat, so four optional looks were prototyped and compared with before/after screenshots (`tools/look-shots.js`): soft gradient lighting, corner shading (ambient occlusion), a drop shadow, and lamp glow (bloom).
    - Each is a 0–1 strength under `look`, set with sliders in the editor's ✨ Look panel, live while dragging.
    - Bloom defaults to half strength and only runs at night. At full strength by day it washed out white surfaces.
    - The post-processing passes load on first use, and the bloom background is inverse tone-mapped so it matches the card colour.

19. **Window daylight (v4.10.1).** The roof keeps direct sun out except through openings, which left rooms with windows as dark as interior ones. Every window, glass door, glass wall or corner glass between a roofed room and the outside now gets a soft, shadowless spot light aimed into the room, scaled by daylight (`_buildSkyLights`, `window_light`). An opening can opt out with `daylight: false`.
20. **Room fill (v4.10.2).** With window daylight in place, the flat daytime ambient and hemisphere fill still lit every surface evenly and washed it out. Its daytime part is now scaled by `ambient` (default 0.35, was effectively 1), with a Room fill slider in the Look panel.
21. **Light settings (v4.11.0).** Bulbs follow their real brightness more closely (1% no longer shows a third of full), are about 60% stronger at full, and each light has sliders for brightness, colour saturation, reach, falloff, beam width and edge, and glow size, applied live while dragging (`_tuneLight`).
22. **Transform fields (v4.12.0).** Every selected item shows position (X, Y, elevation), rotation and size in cm or inches, using `model_scale` (the same scale Set scale fits the blueprint to). Position, rotation and size act on the whole selection, so a group moves, turns and scales as one about its centre (`_transformField`, `_scaleSel`). Resizing is the pure `scaleItem()`; fixed-shape objects store a `size` multiplier, applied about where they hang or stand (`_begin`). Light fixtures, badges and door dots take a `size` too; hotspots a tap radius. Point items with a direction (string lights, aimed lights) get a rotation field.
23. **Three-axis transforms (v4.13.0).** Unity / Godot-style editing: Move, Rotate and Scale gizmos (W / E / R) with all three axes, a Local / Global toggle (X), and an inspector with Position, Rotation, Scale % and Size rows (X across, Y up, Z front to back). Furniture can tilt (`rx`, `rz`; render: outer turn → tilt group about the untilted bounding-box middle `userData.tc`, set up in `_endItem`). Gizmo turns and tilts go through `_applyRotQ`, which swings a group round its middle as one rigid piece; pure turns still use `_applyRotate`. Scale stretches one item along its own axes, or a group evenly. Keyboard turning moved from Q / E to [ / ] in furniture mode.
24. **Room controls (v4.15.0).** Each room can show its own Lovelace cards top right when it is in view (`room_cards`, `_showRoomCards`). They are real HA cards built with `loadCardHelpers().createCardElement`, so anything a dashboard can show works, cached per room and fed `hass` only while visible. The editor's 🎛 Controls panel adds tiles, the room's placed devices in one go, or pasted card YAML (js-yaml, loaded on first use), with a live preview.
25. **See-through room view (v4.16.0).** Framing a room (room menu or double-click) fades the walls and furniture of other rooms that stand between the camera and it. Rays from a grid of points inside the room run towards the camera and are tested against bounding boxes (walls per piece, furniture per item); faded meshes get cached see-through copies of their materials and keep casting shadows. It follows the camera while orbiting, ends on Home or when the view pans away from the room (`_setFocus`, `_updateFade`). `room_fade` sets the opacity, `false` turns it off.
26. **Backdrop light and safe-area centring (v4.17.0).** The stage look's spotlit backdrop was a CSS gradient fixed to the screen, so panning slid the house (and its drop shadow) off its light. It is now a soft-edged mesh on the ground under the house (`_stageSpot`, built with the drop shadow) that only brightens, over a flat card background. Separately, the camera gets a view offset (`_safeArea`, `_applyOffset`) that puts the orbit target in the middle of the part the room controls leave clear: below them on a phone, beside them on a wide screen. Home and room framing fit their zoom to that area, and the offset eases back to normal when the controls are collapsed. In v4.17.2 the safe area also stops above the room bar and nav, Home fits the whole house (floors and lights) as large as the area allows (`_homeView`), and a room framed before its cards finished loading is re-framed when they appear (`_frame` from `_resize`, until a hand moves the view). Since v4.17.3 opening or collapsing the controls always re-frames the room (or home) they belong to, and Home starts selected. In edit mode (v4.17.4) the safe area is the whole card again.
27. **Room controls in any theme (v4.17.1).** With a light HA theme the room control cards turned pale with dark text over the dark map. Their containers now redefine the theme variables (text, card background, dividers, inputs, `--ha-color-*` tokens) to the map's dark palette, which inherit into each card's shadow DOM.
28. **Icon polish (v4.18.0).** Emoji and stray Unicode glyphs on the nav, room bar, editor toolbar, inspector and panels were replaced with Home Assistant's own `ha-icon` (MDI) icons through the shared `ic(name)` helper, with consistent sizing and spacing. Buttons that only had a glyph got tooltips.
29. **Grouped editor toolbar (v4.19.0).** On a phone the icon-only toolbar was unreadable. The toolbar is now a top row (mode switch, undo/redo, Cancel, Save) and a tools row that follows the selection: scene tools (Add, Models, Look, Controls; Blueprint in the plan) show only with nothing selected, item tools (Move, Rotate, Scale, Delete) only with a selection. Less used actions sit in a More menu, and the plan's wall, door, window and room tools in a Draw menu (`_togglePop`). Phones keep labels on everything except undo, redo and delete. Selecting an item closes the Look and Room controls panels. In v4.19.1 Models moved into the Add panel as a Model button beside Box and Label, and on touch screens the entity list scrolls with a finger and a tap adds the entity mid-view (then closes the panel); mouse and pen still drag entities onto the map.
30. **Performance pass (v4.20.0).** three r160's OrbitControls reports a change on every `update()` for an orthographic camera (it always flags the zoom), so the render loop never stopped: an idle map redrew at full frame rate, AO and bloom included. The change handler now checks the camera really moved (`_camMoved`), and an idle map draws nothing. Home Assistant hands over a new `hass` for every state change in the house; the card now applies it once per frame (`_applyHass`, nothing while the tab is hidden) and only redoes the scene when an entity the config mentions, the locale or the location changed, or a minute has passed for the sun (`_hassChanged`, `watchedEntities`). Room control cards still get every `hass`. Door badges, the weather badge and the bloom background colour skip DOM and style work when nothing changed. `npm run test:leaks` gained mode cycling (edit, plan, tools, look panel, room fade), a window/document listener count, an idle-render check and update-burst checks.
31. **3D Home (v5.0.0).** The project was renamed from ha-iso-home and published as its own repository. The card is now `custom:ha-3dhome-card` and the strategy `custom:ha-3dhome`; the old names (`custom:iso-home-3d-card`, `custom:iso-home`) still work and Save writes into either. The core loads the editor from its own folder, because HACS registers only one file. Added `hacs.json`, a tag-driven release workflow, and `site/`: a standalone demo on a fictional home (`examples/sample-home.json`) with a fake `hass`. The tests run on that home too (`tools/fixtures/test-home.json`, the same home with walls in the old format so the migration stays tested). The strategy registers itself in `window.customStrategies`, so on Home Assistant 2026.5+ it is listed under Settings → Dashboards → Add dashboard → Community dashboards. A dashboard made there has no layout, so the card shows an empty-map hint (`_showEmpty`) pointing at Edit → Floor plan. The old names are only claimed when the old ha-iso-home resource isn't installed too (`claimOldNames`, which reads `lovelace/resources`); otherwise whichever module loaded first took them and old dashboards ran either version at random. Home Assistant's Add dashboard dialog has no picture for community dashboards yet (`CustomStrategyEntry` has no image field); a matching one is ready in docs/images/add-dashboard/ (drawn by tools/art/add-dashboard.py).
32. **Connection loss and lost WebGL contexts (v5.1.0).** On-demand rendering (v4.20) meant nothing redrew when a phone or tablet threw away the page's WebGL context in the background, so coming back to HA could leave a blank map. The card now redraws when the context is restored, and rebuilds itself (keeping the camera) when the context stays lost for 3 s on a visible page (`_ctxCheck`). It also follows `hass.connected` and the browser's online state: a drop longer than 2.5 s greys the map under a "Reconnecting to Home Assistant…" pill and taps that would call a service just nudge the pill (`_connState`, `_offlineTap`); Save refuses with a toast and keeps the edits. On reconnect every entity is re-applied and the scene redrawn. After a long sleep, a network change or a back/forward cache restore it pings the websocket and asks HA to reconnect if no answer comes in 8 s (`_probeConn`).
33. **Readable TypeScript source (v5.2.0).** The two large source files (about 4,600 dense lines) became small modules in `src/core`, `src/card` and `src/editor`, formatted with Prettier and written in TypeScript (the config schema is in `src/types.ts`), still bundled into the same two files. Pure helpers are fully strict; the card and editor are strict apart from null checks. Long functions were split into named steps (`_init`, `_update`, pointer input), and the stylesheet moved to `styles.ts`. The editor now loads only when Edit is first pressed (`loadEditor`), so people who only view the map no longer download it. Nothing else changed: every test suite passes unchanged.
34. **A sidebar page of its own (v5.3.0).** On a dashboard the map sat inside Lovelace: every save rewrote the dashboard, Home Assistant replaced the card element and the card had to hand its scene over (`PARKED`), and strategy dashboards were regenerated on every registry change. 3D Home became a Home Assistant integration (`custom_components/ha_3dhome`, HACS category integration) that adds a sidebar page per config entry (`panel_custom`, `<ha-3dhome-panel>`), keeps each page's config and a revision in `.storage`, and pushes every save to all open screens over a websocket subscription. A save that started from an older revision is refused, so two devices can't overwrite each other. The card applies a new layout in its running scene (`_applyLayout`) instead of restarting WebGL, on the panel and on dashboards. The integration serves the card files itself (versioned URLs, so no resource to bump) and loads the card on every page, so the card and the dashboard strategy keep working without a resource. An empty page offers to copy the map from a dashboard. Saving goes through a `LayoutStore` (the dashboard, or the panel's), and the editor became its own object (`Editor`) that the card talks to through `CardEditor` and that reaches the card only through `EditorHost` (`src/editor-contract.ts`), instead of methods copied onto the card.
35. **Only the sidebar page; the editor in Preact (v6.0.0).** The Lovelace card, the dashboard strategy, the old ha-iso-home names, the pre-4.7 wall format and the item types only the first hand-made mockup used (railings, corner glass, glass walls, door panels, plant wall, track, line, bulbs) were removed, and the integration no longer loads the code on every Home Assistant page. An empty page can still copy a map from a 5.x dashboard and brings it up to date. The editor's toolbar, inspector and panels, which were HTML strings with hand-wired listeners, became Preact components (TSX) drawn from the editor's state; Preact (about 5 KB gzipped with its hooks) is bundled into the editor file only, so the map loads none of it. A naming pass split packed declarations to one per line and renamed `it` → `item`, `k` → `kind`, `R1` → `round1` and `_ed` → `_editorLayer`, and the plan geometry was rewritten on a small `vec2` helper. The browser tests share one harness (`tools/harness.js`) that loads the panel with a fake integration.
36. **Phone safe areas (v6.0.1).** Home Assistant pads a custom panel by the device's safe areas (its `--safe-area-inset-*` variables), but the page was sized to the full screen and also added the top inset itself. In the iOS app the sidebar button sat a status bar's height too low and the room bar ran into the home bar. The page is now the screen height less Home Assistant's insets, and adds none of its own.
37. **Open Home Assistant on the map (v6.1.0).** With the dashboard gone, the map could no longer be picked as the default dashboard: the profile page's picker lists only dashboards and a few built-in pages. Home Assistant itself opens whatever panel the user's `default_panel` names (frontend user data, key `core`), any panel included. The map now has a pin button in its nav that sets or clears it for the signed-in user (`HomePage`, handed from the panel as `map.homePage`); the profile page then shows 3D Home as the chosen dashboard, and choosing another there works as before.
38. **Asked once instead of a pin (v6.2.0).** The pin sat on the nav for good. Now a page asks once per user, the first time it shows a map, whether Home Assistant should open on it (remembered in the user's frontend data under `ha_3dhome`, so other devices don't ask again), and the setting moved into a ⋮ menu on the nav (`_toggleMore`). A real dashboard was ruled out: Lovelace always draws its header bar.
39. **No stripes on floors (v6.2.1).** On an iPhone the floors in floor plan mode were covered in dense stripes. The soft-lighting look uses variance shadow maps, and three.js draws every shadow *receiver* into those maps too, so each floor shadowed itself; with the sun overhead in plan mode the floor's depth in the map and on screen were almost equal, and the iPhone GPU's rounding turned that into stripes (desktop showed a few stray dark lines). Floors now carry a depth material that writes nothing (`customDepthMaterial`/`customDistanceMaterial`), so they still receive shadows but never cast them.
40. **Edge to edge (v6.2.2).** With Home Assistant's padding the map stopped short of the screen edges, leaving a plain band under the home bar. Where Home Assistant offers it (`handle_safe_area`), the integration now opts out of that padding: the map draws under the status and home bars, and the panel passes Home Assistant's `--safe-area-inset-*` values to the map as `--ha-3dhome-safe-*`, which every control (viewer and editor) adds to its edge offsets. The camera frames rooms inside the safe box too. Older Home Assistant versions keep the padded page.
41. **Smoother dragging and light changes (v6.2.3).** Every frame drew the ambient occlusion pass, a second render of the whole scene plus a full-screen blur, about a third of a frame's cost (the camera, pointer and render code hadn't changed since 5.x). While the view visibly moves (a drag, a pinch, a flight to a room) that pass now sits out, and it fades back in over 200 ms once the view has been still for 150 ms (`_draw`, `_seenMove`; damping's last sub-pixel steps count as still). A frame where only lights changed reuses the last occlusion, which depends only on the geometry and the camera (`_aoUnchanged`: same camera within sub-pixel tolerances, world and see-through room, no shadow update or door moving, not editing). In a test with 13 lights changing every frame that cut the frame cost by about a third, the same as turning the pass off.
42. **Works without internet (v6.2.4).** Three.js, its add-ons, JSZip and js-yaml came from jsDelivr, so a home whose internet was down got no map. They are now bundled into the integration's files: each loads the first time it's needed from `frontend/lib/` (content-hashed names, gzipped copies alongside), and the core and editor share one Three.js. The `three_url`, `orbit_url`, `jszip_url` and `jsm_url` options are gone. The browser tests refuse every host but the fake Home Assistant, so anything that reaches for the internet fails them.
43. **A faster view outside the editor (v6.2.5).** Outside the editor nothing in the house moves but lights and doors, so two things are now done once instead of every frame. The static meshes are merged into one per material (`mergeGeometries`, colours moved into the vertices): the sample home went from 280 draw calls to 61 and its render submit time from 3.0 to 1.7 ms, a home six times as furnished from 685 calls to 71 (5.5 → 3.0 ms). The corner shading is baked from a top-down height map into a texture every material reads, instead of the GTAO pass (a second scene render plus a full-screen blur): frames cost the same as with the shading off, about a third less than before, and nothing changes while the view moves. The editor keeps the meshes one by one and the live pass. Turning off matrix auto-update was measured too and left out: recomposing the matrices takes about 0.1 ms a frame. Merging exposed a bug in camera flights: one that replaced another restored the view's glide (damping) as it found it, off, so it could stay off for good.
44. **No code for older versions (v6.2.7).** Nothing had been released, so nothing needed carrying over. The empty page no longer offers to copy a map from a 5.x dashboard (with it went the clean-up of retired item types and old string lights), the panel always handles the safe areas itself (`handle_safe_area`, so Home Assistant 2026.8 is now the minimum and the padded-page styles are gone), and the leftover card options and old light marker are no longer stripped. The Python tests run on Home Assistant 2026.10 (Python 3.14).
45. **Baked shading that matches the editor's (v6.2.8).** On a real home the baked map drew a dark line halfway up every wall. The map's footprint took in the backdrop under the house, more than twice its size, so each texel covered about 2 units; and a wall face read the height in front of it through linear filtering, which blends a wall's top with the floor beside it into a ledge at half height, so everything below that line counted as under a shelf. The footprint now holds only what casts shade, heights are read at a texel's centre, the floor-under-something shading applies only to faces looking up, the blur only mixes texels of about the same height (wall tops kept the floor's dark), and walls get the editor's look: a little dark at the floor, and darker up their whole height only in a corner.
46. **Back to live corner shading (v6.2.9).** Even after 6.2.8 the baked shading didn't match the editor's live shading on a real home, most visibly once the lights changed. A map seen from above only knows the topmost surface at each point, so wall faces, corners and anything under something are guesses, and lamplight on the walls shows those guesses up. The GTAO pass is back outside the editor. It still sits out while the view moves, and it is reused on frames where only the lights changed (as in 6.2.3). The merged meshes from 6.2.5 stay: they were the larger part of the saving (280 → 61 draw calls on the sample home).
47. **No freeze after the page opens, and corner shading that stays on (v6.3.0).** For about five seconds after the map appeared the page took no input. That was shader compiling, done twice: the first frames drew straight to the screen, and when the corner shading came in the scene drew into the composer instead, which needs every shader built again (no tone mapping, linear colour). The merged meshes added a few more (colour from the vertices), and the output pass more still. Now nothing draws until the shaders are ready (`_warmShaders`): the post-processing loads first, then the scene, the merged meshes and every pass are compiled for the target they draw into (`_prepareShaders`, `_preparePasses`), and the composer draws every frame, its occlusion pass just switched off when paused. With `KHR_parallel_shader_compile` the driver compiles in the background; without it each shader finishes in its own task. On the sample home under software WebGL the page went from about 6 s blocked (longest stretch 2.7 s, and another one 8 s in) to 2 s (longest 1.1 s, all within the first 2.5 s). The corner shading no longer sits out while the view moves, which looked like flicker; `ao_pause: true` (Look panel) brings that back for slow devices.

## Key decisions

| Decision | Why |
|---|---|
| Layout as JSON in the dashboard config (v4–v5.2) | One source of truth that the in-card editor can save to; no file access to HA needed |
| A custom panel and integration (v5.3) | No dashboard to regenerate on save, live updates across screens, files served with versioned URLs |
| Only the panel (v6.0) | One way in keeps the code small: no element parking, no saving into dashboards, no loading on every page |
| Preact for the editor UI (v6.0) | Components instead of HTML strings and listeners, at about 5 KB gzipped, loaded only with the editor; React would be ten times that, and the 3D map itself stays plain Three.js |
| No geometry library | Three.js covers 3D; the plan maths is a few 2D vector operations (`src/core/vec2.ts`) |
| Plain ES modules, CDN Three.js (until v6.0) | No build step needed in Home Assistant; the dist files were just minified sources |
| Everything bundled, nothing from a CDN (v6.2.4) | The map must keep working when the internet is down; lazy, content-hashed files in `lib/` keep the first load as small as the CDN was |
| Orthographic camera | Keeps the "artsy isometric" look; rooms read like a diorama |
| Squashed heights (`model_scale` [2.1, 4]) | Matches the stylised 60-unit walls instead of real-scale ceilings |
| Downloader integration for SH3D | SourceForge zips aren't CORS-fetchable; HA downloads into `www/` and the browser reads `/local/` |
| Strategy dashboard (v4.1–v5.3) | Full-screen map with no Lovelace chrome; the editor wrote into `strategy` directly. Replaced by the panel in v6.0 |
| Touch: select-then-drag | Panning on a phone kept moving furniture by accident |
